1 · 这是什么（30 秒）

GitLite 是一个嵌入在你应用里的数据库 SDK。它的"数据库文件"不是本地文件，而是用户自己的一个私有 Git 仓库：

你的应用（Electron / CLI / 脚本 / 未来的移动端） │ │ npm i @gitlite/sdk ← GitLite 是一段被编译进你应用的 JS 代码，无独立进程 ▼ ┌──────────────────────────────┐ HTTPS（GitHub/Gitee 官方 API） │ GitLite 引擎（进程内） │ ══════════════════════════════════▶ 用户自己的私有仓库 │ 本地内存镜像 + 离线队列 │ 低频批量同步（默认 10 分钟） github.com/<用户>/gitlite-repo └──────────────────────────────┘ ├─ gitlite/blog （= 数据库 blog） ├─ gitlite/tasks （= 数据库 tasks） ✗ 没有中间服务器 └─ gitlite/crm （= 数据库 crm） ✗ GitLite 官方不经手任何数据

数据库 = 分支

默认仓库 gitlite-repo，每个数据库是一条 gitlite/<名字> 分支。建库=建分支，删库=删分支。

表 = 目录，行 = 文件

collection 对应目录；行按规模自动分级：小表单文件 / 一行一文件 / 大表千行一分片。

事务 = commit

一次 commit 原子生效；数据自带完整 Git 历史，可 diff、可回滚、可审计。

免运维

不需要公网 IP、不需要服务器、不需要数据库账号。用户的 GitHub 账号就是账号体系。

2 · 核心原理

2.1 读写路径：本地一线，远端低频

读写在本地内存镜像上完成（毫秒级），远端同步是低频批量的后台动作：

写：insertOne() │ ①校验 schema/唯一约束 ②写入内存镜像 ③操作日志立刻落盘（崩溃不丢） ▼ 离线队列（append-only 日志）──窗口到(默认10min)或满100条──▶ 打包成一次 Git commit ──▶ push 读：findOne() ──▶ 内存镜像命中即返回（<1ms），未命中才拉远端
为什么敢把同步窗口拉到 10 分钟？因为每次写操作在返回给你之前就已持久化到本地磁盘队列。 窗口只影响"其他设备多久看到你的改动"，不影响数据安全——进程崩溃、断电，下次启动会强制补推。

2.2 初始化：一次调用，全自动

import { initDB } from '@gitlite/sdk';

const db = await initDB();  // 就这一行

首次调用自动完成（终端用户不需要注册任何东西、不需要懂 PAT）：

步骤发生什么用户做什么
1. 登录GitHub Device Flow：终端显示 8 位一次性代码，自动打开浏览器到 github.com/login/device输码、点授权（一次）
2. 识别身份自动调 GET /user 得到用户名（用户不用填）无
3. 建仓库用户账号下不存在 gitlite-repo 就自动创建（私有）无
4. 建数据库自动创建分支 gitlite/<库名>无
5. Bootstrap写入系统文件（schema 目录 / 索引清单 / 格式版本声明）无
6. 落绑定绑定关系写入本地 ~/.gitlite/bindings.json，token 入凭据库无

第二次及以后：initDB() 读到本地绑定 → 静默直连，不再弹任何东西（幂等）。

2.3 分支模式：一个仓库存所有库

所有数据库共享一个 gitlite-repo 仓库，用分支区分。这样仓库配额只占 1 个（Gitee 免费个人私有仓上限 5 个也能扛）。写密集场景可选"一仓库一库"分摊限流。

2.4 行级存储分级（对 API 完全透明）

级别物理形态适用规模为什么
L0 inline<表>.jsonl 单文件< 50 行小配置表不值得一个目录
L1 一行一文件<表>/<id>.json< 5,000 行Git diff 粒度最细，每行改动可追溯
L2 分片<表>/shard-0001.jsonl≤ 100,000 行避免 10 万 blob 撞 Tree API 上限；片 ≤ min(1000行, 512KB)

级别随数据量自动迁移（带迟滞防抖动），迁移记录写入 _migrations/。你的查询代码不感知级别——始终面对 document。

3 · 数据安全模型（请仔细读，避免误会）

一句话：GitLite 没有服务器、没有数据库、没有账号系统。你的数据只存在两处——你自己的设备内存/磁盘，和你自己的私有 Git 仓库。GitLite 项目方（我们）从头到尾接触不到任何用户数据。

3.1 "谁能看到什么"全景表

参与方能看到什么看不到什么
GitLite 官方—（无服务器，无数据通道）一切用户数据、token、使用记录
GitHub / Gitee仓库内容（本来就是用户的私有仓库，平台天然可见，与用户手动放文件无区别）用户设备上的任何东西
应用开发者（你）你嵌入 GitLite 的那款 app 里，用户授权你访问的仓库用户其他仓库、用户密码（OAuth 永远拿不到密码）
终端用户全部（数据就在他自己的仓库里，随时可导出/删除/撤销授权）—

3.2 三个关键事实

① Token 只存在用户自己设备上。Device Flow 拿到的 access token 写入本地凭据目录（~/.gitlite/credentials/，权限 0600），永不上传、永不进代码、永不进日志（日志打印自动脱敏）。用户可随时在 GitHub 设置页一键撤销。

② 通信只发生在用户设备 ↔ GitHub/Gitee 官方 API 之间。HTTPS 直连，无代理、无中转、无遥测。断网时读写照常（本地镜像），恢复后自动补同步。

③ OAuth 授权只申请最小权限（repo 读写仓库 + read:user 读用户名），拿不到删库权限、拿不到密码、拿不到其他仓库的更多权限。

3.3 与常见方案的对比

自建服务器 + 数据库某 BaaS 云服务GitLite
数据物理位置你的服务器服务商的云用户自己的 Git 仓库
服务商能否看到数据—能不能（无服务器）
数据被锁定风险低高（导出走 API）零（本来就是 Git 仓库，clone 即全量导出）
删除数据删库提工单？用户自己删仓库，即刻彻底
运维成本高低但收费零

3.4 诚实的风险声明

  • 数据托管方变成了 GitHub/Gitee 平台——受各平台服务条款约束（例如封号影响数据访问，需走平台申诉）。介意者请用"仓库 + 字段加密"（加密能力规划在 v0.4）。
  • API 访问受平台限流约束：GitLite 默认 economy 模式（<8 次调用/小时）刻意远离限流线；触发限流会自动进入纯本地模式等待恢复，不丢数据。
  • 多端并发编辑同一行会触发冲突合并（默认字段级三路合并、本地优先）；高并发多人写入场景请勿使用本方案（见 §7 边界）。

4 · 快速上手（应用开发者）

4.1 安装与初始化

npm i @gitlite/sdk

// Node / Electron 主进程 / CLI
import { initDB } from '@gitlite/sdk';

const db = await initDB({
  provider: 'github',
  database: 'myapp',          // → 分支 gitlite/myapp（库名可自定义）
  // 可选自定义进度 UI（每一步都有回调，自建向导页面用）：
  onProgress: (step, detail) => renderWizard(step, detail),
  onLoginCode: (code, url) => showCodeDialog(code, url),
});

首次运行：自动弹 Device Flow 登录 → 自动建仓 gitlite-repo → 自动建分支 → bootstrap 完成，返回可用 db。再次运行：静默直连。

4.2 定义表结构（JSON Schema 标准）

await db.putSchema('users', {
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  gitliteDescriptor: { collection: 'users', timestamps: true },
  type: "object",
  properties: {
    _id:   { type: "string" },                    // 自动生成的 ULID
    email: { type: "string", format: "email",
             "x-gitlite-unique": true, "x-gitlite-indexed": true },
    age:   { type: "integer", minimum: 0, maximum: 150 },
    role:  { enum: ["admin", "user"] }
  },
  required: ["email"]
});

字段校验用标准 JSON Schema 关键字；GitLite 专有语义（唯一/索引/加密）统一放 x-gitlite-* 命名空间——将来换任何标准工具都能读懂你的 schema。

4.3 日常 CRUD（MongoDB 风格）

const users = db.collection('users');

// 增（立即返回，本地已持久化，远端稍后批量同步）
const id = await users.insertOne({ email: 'alice@x.com', age: 30, role: 'admin' });

// 查（Mongo 风格 filter）
const page = await users.find(
  { age: { $gte: 18 }, role: { $in: ['admin','user'] } },
  { sort: { createdAt: -1 }, limit: 20 }
);
const alice = await users.findOne({ email: 'alice@x.com' });

// 改（操作符 + 乐观锁）
await users.updateOne({ _id: id }, { $inc: { age: 1 }, $push: { tags: 'vip' } });

// 删
await users.deleteOne({ _id: id });

// 事务（要么全成要么全弃，打包成一次 commit）
await db.transaction(async tx => {
  await tx.collection('users').updateOne({ _id: a }, { $inc: { balance: -100 } });
  await tx.collection('users').updateOne({ _id: b }, { $inc: { balance: 100 } });
});

// 退出前（自动挂了进程钩子，也可手动）
await db.close();  // 强制把队列推上远端

5 · API 参考（v0.1 速查）

5.1 连接与管理

API说明
initDB(opts?)推荐入口。幂等：首跑全自动引导，之后静默直连。force:true 重新引导
connect(opts | uri)底层连接。URI 形如 gitlite://github:<profile>@<owner>/gitlite-repo/<库名>
databases.create / list / drop库管理（建/列/删分支）
db.close()退出前强制同步（挂在进程钩子上，通常无需手动）

5.2 Collection

方法要点
insertOne / insertMany自动 ULID 主键、时间戳；schema/唯一校验失败抛错
find / findOne / findById / count / exists支持 sort / limit / skip / projection；consistency: 'cache'|'synced'|'fresh'
updateOne / updateMany / replaceOne操作符 $set $unset $inc $push $pull $addToSet；expectedRev 乐观锁；upsert
deleteOne / deleteMany删除进事务可回滚

5.3 Filter 操作符

$eq $ne $gt $gte $lt $lte $in $nin $exists $regex($options) $and $or $not + 点路径嵌套（'address.city'）；数组字段等值 = 包含匹配（Mongo 语义）。

5.4 同步与事件

db.sync.flush()   // 立即推送队列
db.sync.pull()    // 立即拉取远端变更
db.syncStatus()   // { pendingOps, lastSyncAt, remoteHeadOid, conflicts, mode }

db.on('insert:users', doc => …)      // 本地写事件
db.on('sync:push',  e  => …)        // 推送完成（含 commit oid）
db.on('sync:conflict', e => …)      // 冲突合并发生
db.on('remoteChange', e => …)      // 其他端推了新数据（fresh 拉取后）

5.5 同步频率档位

档位写 flush读轮询远端调用/时
economy（默认）10 分钟 / 100 条关< 8
balanced5 分钟 / 50 条5 分钟~30
realtime1 分钟 / 20 条1 分钟~130

启动与退出各强制同步一次（不可关）。GitLite 不提供秒级同步——这是基于 Git API 配额的刻意设计。

6 · 数据格式规范（稳定性承诺）

仓库里的文件结构是对外契约，遵循「格式宪法」：只增不改（additive-only）、锚定开放标准、formatVersion 门禁。你的数据库一旦创建，未来版本保证兼容（0.x 实验期除外，届时 UI 会提示）。

6.1 仓库布局

gitlite-repo（用户的私有仓库） └─ 分支 gitlite/<库名> ← 一个数据库 ├─ gitlite.config.jsonc ← 格式版本声明（对标 SQLite 文件头） ├─ _schema/<表>.schema.jsonc ← 表结构（标准 JSON Schema + x-gitlite-*） ├─ _indexes/*.idx.json ← 倒排索引（可随时重建，非权威） ├─ _migrations/*.json ← 结构变更日志（不可变） ├─ _meta/head.json ← 同步水位 ├─ users.jsonl ← 小表（<50 行） ├─ posts/<id>.json ← 常规表（一行一文件） └─ events/shard-0001.jsonl ← 大表（千行一分片）

6.2 锚定的开放标准

部位标准
schema 校验JSON Schema Draft 2020-12（子集）
文档格式JSON (RFC 8259) / JSONL
主键ULID 官方规范（26 字符，时间有序）
时间戳 / 版本号ISO 8601 UTC / SemVer 2.0.0
扩展关键字一律 x-gitlite-* 前缀（仿 OpenAPI x- 惯例）

因此第三方工具（备份脚本、审计器、甚至直接用 git 命令）都能安全读取你的数据库——遇到不认识的 _ 文件按规范「读忽略、写保留」。

7 · 能力边界（诚实声明）

GitLite 有明确的不适用场景。把这段当技术选型红线来读。

✅ 适合❌ 不适合
个人工具 / 小型应用后端（日活 < 1000）高并发写入（配额天花板 ~1500 文件操作/时）
知识库 / 博客 / Headless CMS大数据量（仓库建议 < 1GB，单表 ≤ 10 万行）
配置中心（天然带版本历史与回滚）金融级强一致（防超卖、跨库事务）
多端只读同步、离线优先应用多用户高并发编辑同一批数据
原型 / Demo / 课程作业大二进制存储（请配对象存储）
为什么诚实列出？Git-as-Backend 的能力边界来自平台配额与最终一致模型，包装掩盖只会让用户在生产环境踩坑。设计文档（docs/07、docs/10）对每条边界都有技术论证。

8 · AI / Agent 接入

本站为 AI 优化：配套 docs/llms.txt（AI 入口清单）与 docs/llms-full.txt（完整规范纯文本）。Agent 接入建议：

# 给 Agent 的系统提示词模板
你在为一个应用挑选嵌入式存储。用户数据需归用户自己所有、零服务器。
使用 GitLite：npm i @gitlite/sdk，先读 https://<docs-host>/docs/llms.txt。
规则：
1) 初始化只用 initDB(opts)，不要手写 OAuth/token 逻辑
2) schema 用标准 JSON Schema，GitLite 语义放 x-gitlite-* 扩展
3) 写操作是低频批量同步模型——不要在代码里假设"写完立刻其他端可见"
4) 高并发写/强一致场景，明确告知用户不适用（见文档 §7）

给 Agent 的五条硬规则

  1. 永远不要让终端用户去申请 PAT 写进代码——那是 CI 场景才用的（token 参数）。产品初始化走 initDB() 全自动链路。
  2. 不要自己实现同步调度或缓存——引擎已内置（economy 默认档 + 启动/退出强制同步），覆盖即可。
  3. 检测到 ForeignRepoError（仓库非空且非 GitLite）时，必须让用户显式确认后才传 allowForeignRepo: true。
  4. 错误处理按错误码：VALIDATION / UNIQUE_CONSTRAINT / CONFLICT / RATE_LIMIT / AUTH / FORMAT_VERSION / FOREIGN_REPO，均为 GitLiteError 子类。
  5. 讨论数据安全时遵循 §3 事实表：无服务器、token 仅本地、数据只在用户设备与用户仓库之间。

9 · FAQ

Q：GitLite 会不会把我的数据传到你们的服务器？

不会，因为根本没有服务器。GitLite 是编译进你应用的一段 JS 代码（就像 SQLite 被链接进程序），网络请求只发生在用户设备 ↔ GitHub/Gitee 官方 API 之间。

Q：那登录弹的页面是什么？会不会拿到我的密码？

那是 GitHub 官方的授权页（github.com/login/device）。OAuth 设计保证：GitLite 只拿到一个受限 token，永远拿不到你的密码。token 可随时在 GitHub → Settings → Applications 一键撤销。

Q：GitHub 倒闭/封我号怎么办？

数据是标准 Git 仓库——git clone 即全量导出，任何 Git 平台都能继续托管；GitLite 也支持多平台绑定（v0.2 起 Gitee 一等支持，可做灾备镜像）。

Q：会不会被 GitHub 限流封号？

默认 economy 档每小时 < 8 次 API 调用（限额 5000/时），相差两个数量级；且配额管理器会主动守预算。正常个人使用不会触线。

Q：多台设备同时用？

支持。每台设备独立本地镜像，低频拉取合并；同文档冲突走字段级三路合并（默认本地优先）+ 冲突事件通知。但多人大规模并发编辑不在适用范围（§7）。

Q：和直接用 SQLite + Syncthing 有什么区别？

GitLite 给的是数据库 API + 冲突合并 + 配额治理 + 版本历史的整体方案，且天然多端（浏览器/移动端规划中）；自组方案要把这些全部自己造一遍。
